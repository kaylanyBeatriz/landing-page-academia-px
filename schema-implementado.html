2. O que a landing page NÃO consegue fazer (por desenho)

A chave pública (anon) usada no front não tem permissão de leitura/escrita em nenhuma tabela acima — só executa as 4 funções da seção 3. Isso é o que garante que o link do arquivo não vaza antes do cadastro (gated content).

3. Funções (RPC) consumidas pela LP — script.js

3.1 lp_list_materials carregamento da página

POST /rest/v1/rpc/lp_list_materials
{ "p_lp_slug": "curso-nr-35" }

Retorna a lista de materiais ativos da LP (sem links de download) para montar a grid. Chamada em loadMaterials().

3.2 lp_validate_token carregamento da página

POST /rest/v1/rpc/lp_validate_token
{ "p_token": "<token salvo no localStorage>" }

Se houver token salvo (academia_kit_nr35_token), valida a sessão e libera o acesso automaticamente, sem pedir o formulário de novo. Token inválido/expirado é removido.

3.3 lp_register_lead envio do formulário

POST /rest/v1/rpc/lp_register_lead
{
  "p": {
    "lp_slug": "curso-nr-35",
    "full_name": "…", "job_title": "…", "email": "…",
    "phone": "…", "company": "…",
    "consent_given": true, "consent_version": "v1",
    "utm_source": "…", "utm_medium": "…", "utm_campaign": "…",
    "utm_content": "…", "utm_term": "…", "gclid": "…", "fbclid": "…",
    "referrer": "…", "landing_page": "…"
  }
}

Resposta: { "access_token": "…", "expires_at": "…" } — salvo em localStorage e usado para liberar a grid. Reenviar o mesmo e-mail atualiza o lead existente em vez de duplicar.

3.4 lp_register_download clique no card

POST /rest/v1/rpc/lp_register_download
{ "p_token": "…", "p_material_id": "…uuid…" }

Chamada só no clique (nunca no carregamento) — o link expira em 5 minutos. Resposta: { "download_url": "…", "expires_in": 300, "name": "…" }. Token inválido (erro 28000) limpa a sessão e reexibe o formulário.

3.5 lp_check_email login — checagem

POST /rest/v1/rpc/lp_check_email
{ "p_lp_slug": "curso-nr-35", "p_email": "…" }

Não fazia parte do contrato original — criada sob demanda pra viabilizar o login só com e-mail. Retorna true/false, sem expor nome ou qualquer outro dado. Usada em api/register-lead.php (decide se notifica o admin) e como checagem prévia ao login.

3.6 lp_resend_access login — recupera acesso

POST /rest/v1/rpc/lp_resend_access
{ "p_lp_slug": "curso-nr-35", "p_email": "…" }

Também criada sob demanda. Devolve access_token + full_name + expires_at do lead já cadastrado, sem exigir full_name de novo — evita sobrescrever o nome real ao "logar" só com e-mail. Retorna vazio se o e-mail não existir. Rate limit: 10 chamadas/minuto por IP (tabela lp_resend_requests). Usada em api/send-login.php.

4. Backend PHP (api/)

Como o envio de e-mail exige uma credencial secreta (senha de app do Gmail) que não pode ficar no script.js público, o cadastro completo e o login passam por dois endpoints PHP antes de tocar no Supabase:

ArquivoFunção
api/register-lead.phpRecebe o formulário completo, chama lp_check_email + lp_register_lead, e dispara e-mail de aviso (ADMIN_NOTIFY_EMAILS) só em cadastro novo de verdade.
api/send-login.phpRecebe só o e-mail, chama lp_resend_access, e manda por e-mail um link ?login_token=… — o acesso só libera quando a pessoa clica.
api/mailer.phpEnvio via SMTP do Gmail (smtp.gmail.com:465), implementado com sockets puros do PHP, sem biblioteca externa.
api/config.phpNão versionado. Guarda a senha de app do Gmail e os demais segredos/config. Copie de api/config.example.php.
A sessão liberada no navegador expira em 15 minutos (client-side, via localStorage — não é uma expiração real do access_token, que continua valendo 180 dias no banco).
